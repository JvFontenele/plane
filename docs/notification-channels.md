# Notification Channels — Telegram and WhatsApp

## Overview

Notification channels deliver Plane in-app notifications to external messaging services. Two channels are supported:

- **Telegram** — a single bot per installation, configured once in God Mode.
- **WhatsApp** — a single Evolution API instance per installation, configured once in God Mode.

No notification is sent through a channel unless the channel is linked to the user and the user has explicitly consented.

## Setup

### Telegram

1. Create a bot via [@BotFather](https://t.me/BotFather) on Telegram.
2. In God Mode, navigate to **Notifications** and paste the bot token into the `TELEGRAM_BOT_TOKEN` field.
3. Click **Verify bot**. This calls `getMe` and stores the bot username.
4. Enable the channel.

The bot must **not** have a webhook configured. Linking uses `getUpdates` to read incoming messages.

### WhatsApp

1. Run [Evolution API](https://github.com/EvolutionAPI/evolution-api) (Apache 2.0) in Docker using the `atendai/evolution-api` image. Set the environment variable `AUTHENTICATION_API_KEY`.
2. In God Mode, provide the Evolution API URL, API key, and instance name.
3. Click **Connect**. A QR code is returned; scan it with the phone to pair the device.
4. Enable the channel.

> **Warning:** Evolution API is not an official WhatsApp product. It is built on WhatsApp Web via Baileys. There is a risk of number ban or session drop. For higher volumes, consider the official WhatsApp Business Cloud API (paid, with approved templates).

## Migrations and Settings

Apply the migration:

```bash
python manage.py migrate
```

This is migration `0124_notification_channels`.

Required settings:

- **`WEB_URL`** — base URL of the **web app** (e.g. `https://plane.example.com`), used in notification links. The `.env.example` default points to the API (`:8000`); change it or links will open the API instead of the work item.
- **`NOTIFICATION_DELIVERY_RETENTION_DAYS`** — number of days to keep `NotificationDelivery` records (default: 30).
- **8 instance configuration keys** in category `NOTIFICATIONS` — Telegram bot token, WhatsApp API key, Evolution API URL, instance name, and the four keys used internally. These can also be provided as environment variables via `configure_instance`.

## User Flow

Users manage channels in **Account Settings → Notifications**.

1. **Link Telegram** — user clicks a link generated by the `telegram/link/` endpoint. The link is a deep link to `t.me/<bot>?start=<token>`. The token is random, valid for 15 minutes, and single-use. The backend stores only the hash.
2. **Verify Telegram** — user clicks "Verify" in the UI. The backend calls `getUpdates` and looks for the `/start <token>` message to extract the `chat_id`.
3. **Link WhatsApp** — user enters their phone number in E.164 format via the `whatsapp/link/` endpoint. A 6-digit code is sent by the Evolution API instance.
4. **Verify WhatsApp** — user enters the code via `whatsapp/verify/`. Maximum 5 attempts, code valid for 10 minutes, one send per minute.
5. **Enable a channel** — setting `enabled=true` requires a verified link and records `consented_at`.
6. **Disable a channel** — setting `enabled=false` revokes consent and clears `consented_at`.
7. **Choose events** — per channel, the user selects which event categories they wish to receive. An empty list means all events allowed.
8. **Unlink** — deleting the channel removes the link and consent.

## Delivery Rules

A notification is sent through a channel only when **all** of the following are true:

1. The channel is globally enabled and configured in God Mode.
2. The channel is linked and the user has consented.
3. The event category is allowed by the admin policy (`NOTIFICATION_CHANNEL_EVENTS`).
4. The event category is allowed by the user's per-channel preference. An empty list means all categories are allowed.
5. The recipient is still an active member of the project.
6. The rate limit of 20 messages per minute is not exceeded.

If any condition fails, the delivery is marked as `skipped` with the corresponding reason:

| Reason                     | Meaning                                                     |
| -------------------------- | ----------------------------------------------------------- |
| `channel_disabled`         | The channel is disabled globally in God Mode.               |
| `not_linked_or_no_consent` | The user has not linked the channel or has not consented.   |
| `event_disabled_by_admin`  | The admin policy does not allow this event category.        |
| `event_disabled_by_user`   | The user opted out of this event category for this channel. |
| `no_project_access`        | The recipient is no longer an active member of the project. |
| `rate_limited`             | The 20 messages/minute limit was exceeded.                  |

Retries: up to 3 attempts with exponential backoff via Celery.

Status values:

- `pending` — queued.
- `sent` — accepted by the provider (this is not proof of delivery to the end user).
- `failed` — all retries exhausted.
- `skipped` — one of the rules above prevented sending.

## API Reference

### Admin endpoints (requires `InstanceAdminPermission`)

Prefix: `/api/instances/notification-channel/`

| Method  | Path                | Description                                                                    |
| ------- | ------------------- | ------------------------------------------------------------------------------ |
| `GET`   | `/`                 | Returns `telegram_set` / `whatsapp_set` (boolean). Secrets are never returned. |
| `PATCH` | `/`                 | Update configuration. An empty secret keeps the current value.                 |
| `GET`   | `telegram/check/`   | Calls `getMe` and stores the bot username.                                     |
| `GET`   | `telegram/test/`    | Sends a test message to the linked Telegram bot.                               |
| `GET`   | `whatsapp/status/`  | Returns the instance connection state.                                         |
| `GET`   | `whatsapp/connect/` | Triggers QR generation. Returns QR as base64 + pairing code.                   |
| `POST`  | `whatsapp/logout/`  | Disconnects the paired device.                                                 |
| `GET`   | `whatsapp/test/`    | Sends a test message to the specified number.                                  |
| `GET`   | `delivery-log/`     | Last 50 failed or skipped deliveries, with reason. No personal data.           |

### User endpoints

Prefix: `/api/users/me/notification-channels/`

| Method   | Path               | Description                                                                 |
| -------- | ------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET`    | `/`                | Lists all channels and their configuration.                                 |
| `PATCH`  | `<telegram         | whatsapp>/`                                                                 | Update `enabled` and `events` for a channel. `enabled=true` requires a verified link and records consent. `enabled=false` revokes consent. |
| `DELETE` | `<telegram         | whatsapp>/`                                                                 | Unlinks the channel and removes consent.                                                                                                   |
| `GET`    | `telegram/link/`   | Returns a deep link `t.me/<bot>?start=<token>` (15 min, single-use).        |
| `POST`   | `telegram/verify/` | Verifies the link by reading `getUpdates` for the `/start <token>` message. |
| `POST`   | `whatsapp/link/`   | Sends a 6-digit verification code to the given phone number (E.164 format). |
| `POST`   | `whatsapp/verify/` | Accepts the code. Max 5 attempts, 10 min validity, one send per minute.     |

## Limitations

- No per-workspace notification policy. The admin policy (`NOTIFICATION_CHANNEL_EVENTS`) applies to the entire installation.
- No delivery confirmation. The status `sent` means the provider accepted the message; it does not mean the end user received it.
- Evolution API is not an official WhatsApp product. Use at your own risk.
